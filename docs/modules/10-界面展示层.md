# 界面展示层

模块 ID：`gui_presentation`

本页默认按软约束和背景说明理解。真正硬约束只以 `docs/01-系统架构总览.md`、`docs/02-模块地图.md`、`docs/03-共享瓶颈点.md` 的机器可读契约为准。

## 模块定位

本模块负责所有直接面向用户的 Qt 展示与交互组件。它的职责是展示状态、收集输入、触发稳定入口，不负责定义库存规则、导入策略或工具契约。

如果一个改动的目标是“让界面显示正确、交互顺手、输入可控”，它大概率属于本模块。

## 拥有路径

- `app_gui/ui/`

## 主职责

- 面板内局部交互状态
- 用户输入约束与前端提示

## 与其他模块的边界

### 与 `gui_application` 的边界

- 展示层负责“显示什么按钮、输入什么值、触发什么稳定调用”
- 应用层负责“这次操作要怎么编排、怎么跨面板同步、怎么发布事件”

### 与 `inventory_core` 的边界

- 展示层可以显示来自核心层的数据
- 展示层不应决定核心字段规则、工具契约、写入顺序或审计策略
- 与位置索引相关的显示面（例如 Overview、Plan、打印预览、导出前展示）默认复用 `lib.position_fmt` 的显示 helper，不要在 UI 里手拼 `box:position` 或直接暴露内部整数位置。

### 与 `agent_runtime` 的边界

- 展示层只能展示 agent 的结果和事件
- 不要把 agent 的推理、恢复策略、工具选择逻辑塞回 UI
- AI 面板的流式展示按 agent 事件的 `meta.channel` 做视觉分流：`thought` 只进入思考面板，`answer` 只进入最终回答区域。
- `thought` 是展示层局部状态，不是最终回答正文；UI 不应自行解释 reasoning、tool results 或历史拼接语义。
- 思考面板仅在 `thought` chunk 活跃输出期间临时显示；一旦进入 `answer`、工具边界或流结束即自动隐藏，不保留历史 reasoning 展开入口。

## 盒展示语义

- UI 可以显示盒子的可选标签，但必须继续把数字盒号作为真实定位键。
- 概览、打印、导出等展示面可以把标签作为补充信息展示，不要让标签单独承担身份语义。
- 与 `meta.box_layout.box_tags` 相关的用户文案可以继续使用“Tag / 标签”，但不要暗示底层盒身份已改成字符串。

## 公共主题与控件状态

- 公共主题统一提供 10px 滚动条和最小 36px 滑块，不为单个面板重复覆盖尺寸或手动重刷滚动条样式。输入控件与按钮切换焦点时只改变颜色，保持边框宽度与内容几何不变；语义按钮共用禁用态。

## Overview 交互语义

- 库存表格选中前后使用相同文字布局，只改变行背景，不叠加单元格原生焦点框；保留键盘导航和双击/F2 编辑。行内编辑器使用固定的一像素边框，避免焦点切换改变内部尺寸。
- Pending 计划表默认按可用宽度分配列宽，摘要最多显示可容纳的多行，超出时省略。选中任务后，下方只读详情展示完整位置、变更与状态信息，可选取复制；完整详情纵向滚动，不要求横向拖动。窗口变宽/变窄时重新适配列宽，刷新任务内容不按最长文本撑宽列。计划表滚动条加宽到 10px，保留像素滚动和列宽手动调整。

- `OverviewPanel` 网格中的占用格，单击默认用于预填到操作面板；不要把普通浏览、点选或短距离拖动直接判定为移动操作。
- 从概览网格发起移动，默认采用”长按后拖拽”这类防误触手势，再通过 `plan_items_requested` 进入计划区；展示层不应在拖拽完成时直接执行写入。
- 表格视图中已暂存的计划项可以通过 `plan_item_removal_requested` 信号请求移除；该信号连接到 `OperationsPanel.remove_plan_items_by_payload`，由操作面板侧统一操作 `PlanStore`。
- 长按时长、拖拽距离这类参数属于展示层内部交互策略，默认按软约束记录在本模块文档与对应 GUI 测试中，不上提到顶层硬契约，除非它已经变成跨模块共同依赖的稳定边界。
- 空格上若存在 `plan_store` 的待执行 add 操作（`action == "add"` 且 payload 覆盖该 position），概览网格应在格内把 `display_key` 的待填值以占位样式显示出来，而不是继续显示位置号；`plan_model.apply_operation_markers_to_grid` 的打印视图需表达同一语义。锁测试位于 `tests/unit/test_overview_panel_add_preview.py` 与 `tests/integration/plan/test_plan_model.py`（`test_apply_operation_markers_attaches_preview_label_for_add` 等）。
- Overview 网格与表格的默认关键词搜索不应匹配内部记录 ID；ID 列仍可展示、排序和列筛选，精确记录定位应使用显式 `record_id` 入口。
- 表格视图默认处于当前库存语境时，不显示 `thaw_events` / `storage_events` 这类历史事件列，也不让隐藏的历史事件列参与列筛选、排序回退或关键词匹配；打开“历史/已取出”视图后再显示这些事件列。
- 表格列头的筛选入口只响应漏斗图标本身；靠近列分隔线的区域保留给 Qt 原生列宽拖拽，避免用户调整列宽时误开筛选弹窗。锁测试位于 `tests/integration/gui/test_gui_panels_data_views.py::OverviewTableViewTests::test_filterable_header_click_target_excludes_resize_handle`。
- Staged Plan 表格滚动默认采用像素级滚动，并使用较小的水平/垂直 single-step，避免滚动条或滚轮一次跳过过多内容。锁测试位于 `tests/integration/gui/test_gui_panels_ops_settings.py::GuiPanelsOpsSettingsTests::test_plan_table_scroll_uses_precise_pixel_steps`。

### OverviewPanel 内部结构（软约束 / 背景）

- `OverviewPanel` 体量较大，内部按职责拆分为若干协作对象，主类在 `__init__` 构造它们并通过委托方法调用：
  - `overview_panel_zoom.OverviewZoomController`：缩放与盒导航（独占持有缩放/滚动动画对象）。
  - `overview_panel_runtime.OverviewRuntimeController`：`eventFilter` 分发、网格键盘/滚轮/悬停、视图模式切换、筛选防抖。
  - `overview_panel_refresh.OverviewRefreshController`：读快照数据加载刷新流水线。
  - `overview_panel_filters.OverviewFilterController`：网格/表格筛选与列筛选弹窗。
  - `overview_panel_interactions.OverviewInteractionController`：单元格点击/悬停/右键菜单与拖拽落点。
- 状态各有一个所有者：选择态归 `GridSelection`，查询状态归 `OverviewQueryState`，录入草稿归 `TableEntryDraftStore`，缩放动画归 zoom 控制器；悬停态、表格/网格快照仍由面板持有。跨面板通过 `selected_slot()` 读取不可变的活动格快照，不访问选择模型内部字段。
- `overview_panel_grid`（网格渲染）、`overview_panel_table`（表格渲染与编辑）、`overview_panel_ui`（控件树构建）保留 partial-class 绑定。查询由独立模块接受显式输入，选择模型负责状态转换与导航几何，渲染层不再维护另一套状态或查询算法。

### 表视图增量渲染契约

- `app_gui/ui/overview_panel_table._render_table_rows` 默认走「按行签名对比」的增量路径：同一行的 `row_kind / box / position / record_id / color_value / row_confirmed / row_locked / 展示列值` 未变时，跳过 `setItem`。
- 当行数变化、列集合变化或列类型映射变化时回退到整表 `setRowCount + 重建`；这是唯一允许重建的触发点，其他刷新路径不得重新调用 `setRowCount(0)`。
- `_refresh_table_entry_row_visual` 单行重绘后，必须同步更新缓存签名，避免下一次批量渲染误判「已同步」。
- 该契约的锁测试位于 `tests/integration/gui/test_gui_panels_data_views.OverviewTableViewTests::test_render_table_rows_uses_set_row_count_batch_path` 与同类 `test_render_table_rows_only_rewrites_changed_rows`；若要改变签名字段，请同步更新这两处与本节文字。

## 主题与样式资源（软约束）

- 视觉 token（颜色、边框、状态色）放在 `app_gui/assets/qss/light.qss` 与 `dark.qss` 的 `:root { --token: value; }` 块中。
- 共享控件样式放在 `app_gui/assets/qss/common.qss`，用 `var(--token)` 引用 token，用 `{FONT_SIZE_MD}` 之类占位符引用 `app_gui/ui/theme.py` 顶部的字号/字重常量。
- Qt QSS 本身不支持 `:root` / `var()`，`theme.py` 在应用前展开；`get_theme_tokens()` / `resolve_theme_token()` 供 Python 侧读取同一套 token。
- 只改颜色、间距、控件外观时优先改 `.qss` 文件，不要在组件里散落 `setStyleSheet` 与十六进制色值。
- 下拉箭头、微调按钮、勾选图标由 `theme.py` 按主题颜色把 Lucide SVG 写入临时目录后以 `url()` 引用，新增此类图标走同一机制。

## 适合的任务切分方式

适合并行拆分为：

- 单个面板内的布局重构
- 某个对话框或表格的交互细化
- 某个 UI 子模块的视觉与输入限制调整

不适合并行拆分为：

- 多个任务同时改同一个面板的公共方法签名
- 一边改 UI，一边改主窗口 wiring

## 典型反模式

- 为了“先能跑”，在 `app_gui/ui/` 里直接写工具调用编排
- 让 UI 组件直接导入底层写校验模块
- 依赖另一个面板的私有字段或私有方法
- 在 UI 层复制业务规则，导致 GUI 与 agent 行为不一致

## 查询与草稿状态归属（软约束）

Overview 查询的排序、列筛选和候选值缓存由 `OverviewQueryState` 管理；面板与协作组件直接使用该对象，不保留旧字段别名。数据变化统一使候选值缓存失效。表格录入草稿与暂存投影只由 `TableEntryDraftStore` 提供，不保留无 store 的第二条实现。组件拆分属于内部实现，不扩大跨面板稳定接口。

## Overview 组件依赖（软约束）

Overview 表头排序统一通过查询状态触发核心查询，在全部匹配行排序后再分页。Qt 表格按查询返回顺序渲染，不另行排序当前页；空值末尾和类型比较均使用核心查询规则。

表格数据角色由独立的 overview_table_roles 模块提供；表格、编辑器、筛选对话框与菜单直接导入其定义模块，不反向导入 OverviewPanel。当前库存表格查询通过显式数据与草稿解析函数完成，筛选控制器负责选择当前/历史查询路径。网格选择状态由无 Qt 依赖的 GridSelection 管理，网格只负责收集可选位置并绘制变化；不保留旧面板状态属性兼容层。

单行编辑与整表查询统一经 TableEntryDraftStore.resolve_rows 解析草稿/暂存状态，不另写单行状态算法，也不通过行字典暗传列定义。表格读取日期编辑值时同步 stored_at/frozen_at 输入别名，避免清空后旧值回填。

未绑定 PlanStore 时展示空计划；绑定后使用其 list_items 契约。内部读取异常必须保留真实原因，不得用空列表替代并清除暂存状态或网格标记。

网格与表格的新增/取出预填统一由 OverviewInteractionController 生成载荷并发出原有信号；前台/后台新增预填仅在信号与文案上区分。主面板不保留旧预填函数绑定，表格模块不承担网格共享交互。设置/清除盒标签共用提交后的提示和通知处理，写入仍通过已有 bridge 完成。
