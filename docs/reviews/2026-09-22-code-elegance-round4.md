## R11. 表格与核心查询双重排序

- 严重程度：高；模块：gui_presentation；共享瓶颈点：否。
- 位置：overview_panel_table 的 _SortableOverviewItem、类型转换 helper、_on_table_sort_changed。
- 证据：表头变化只改 query state，Qt 再排序当前最多 500 行，未对全部匹配数据重新查询；Qt 比较器也重复核心的数字/日期/位置规则。
- 目标：核心查询唯一负责排序与分页，表头变化触发查询；Qt 仅按结果顺序渲染，删除比较器和类型解析副本。
- 回归：真实表头点击、超过 500 行全局排序、空值末尾、数字排序、历史视图与增量重绘。
- 状态：已完成；生产代码净减少 123 行。
- 结果：删除 Qt 自定义比较器及类型/位置排序副本；表头更新查询并恢复确认列的有效排序指示，控件不重排查询结果。
- 验证：原数据视图 63 passed；新增全局分页排序与真实表头点击/双向空值末尾 2 passed。

## R12. 计划读取错误伪装为空计划

- 严重程度：高；模块：gui_presentation；共享瓶颈点：否。
- 位置：TableEntryDraftStore.staged_slot_map、overview_panel_grid._on_plan_store_changed。
- 证据：list_items 任意异常均转换为 []，让程序错误表现为暂存项/网格标记消失。
- 目标：保留未绑定 store 的合法空状态；已绑定对象遵守 list_items 契约，异常保留真实原因，不能清除现有标记。
- 回归：未绑定/正常/故障 store、失败后标记和草稿保留。
- 状态：已完成；生产代码净减少 10 行。
- 结果：保留 None 表示未绑定的合法状态；删除 list_items 方法猜测与吞异常分支，读取失败不会清除标记或草稿。
- 验证：草稿 store 与 Overview 78 passed、7 subtests passed；原始异常对象保留，损坏绑定显式失败，解绑正常清空标记。

## R13. 主窗口绕过应用用例的第二条路径

- 严重程度：中；模块：gui_application；共享瓶颈点：main.py。
- 位置：_dispatch_operation_completed、_request_migration_mode_change。
- 证据：构造函数无条件创建两项用例并接入事件总线；入口仍在缺用例时直接刷新/切换状态，部分测试专门锁定未装配窗口的旧兜底。
- 目标：入口只调用已装配用例；事件发布和订阅只走一条路径，装配错误不被静默旁路。
- 回归：真实用例向事件总线发布、消费者收到事件、缺失依赖显式失败、主窗口流程集成测试。
- 状态：已完成；生产代码净减少 8 行。
- 结果：MainWindow 两个分发入口只调用构造时已装配的用例；删除缺失用例时直接执行 UI 处理器的旁路。
- 验证：主窗口流程、事件分发与架构依赖 49 passed、5 subtests passed。旧旁路测试改为真实用例与事件总线联通测试，新增缺依赖显式失败且不执行 UI 回调的测试。
